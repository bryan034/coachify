# Roadmap

`roadmap-planner.tsx` is the shell: it loads and polls the workspace, sends messages and writes, and recovers lost responses. It shows one of two views, each with a button that opens the chat helper.

- **Configure:** `settings-panel.tsx` is the fixed planner form and the confirmed record, with `blackout-rules.tsx` for repeating blackout days and time slots. Every runway number and duration resolution comes from `POST /planner/runway`.
- **Generating:** Generate stays disabled until the required fields are filled; `missingFields` and the backend's runway list what is left. Blackouts and learning focus stay optional. After the click, `generation-screen.tsx` replaces the page with a progress bar that follows the saved operation's stages, then the preview opens. A failure returns to the form with a retry.
- **Preview:** `roadmap-review.tsx` shows a new roadmap before acceptance, and older `roadmap-v2` plans read-only with a prompt to start a new roadmap. `RouteMap` draws the plan as a rising route to the goal; the numbered milestone list in `milestone-timeline.tsx` carries the same facts as text.
- **Accepted roadmap:** `active-roadmap.tsx` runs in this order: header, Today, Coach, Weekly roadmap, Backlog and deferred scope, then secondary details. `task-item.tsx` holds task actions and the move and custom-task forms. `coach-panel.tsx` holds the check-in, pace warning, action-needed tasks, recent moves with Undo, and previews. The page only displays backend numbers; rule failures are explained beside the action, and only unconfirmed writes use the recovery notice.
- **Edit plan and Start new roadmap:** both reuse the planner form. Edit prepares a preview and saves nothing else. Start new is pre-filled from current settings, starts today and generates a candidate while the current roadmap stays active.
- **Next field:** `planner-guide.ts` picks what the chat helper shows after its latest message: the planner section and field to fill in next, from the runway's issues and then the empty optional sections. It is derived from form state, so it stays correct whatever the model replies.
- **Chat helper:** closed, the view fills the screen with two columns on wide screens: the form beside a pinned runway, and milestones and sessions beside outcomes and gaps. Open, `adviser-chat.tsx` docks beside the view, which narrows to one column, or overlays it on narrow screens. It starts on the first required detail the runway reports as missing, lists what is still needed, and fills in the form. With a plan, it requests a preview of settings or unfinished generated tasks. It closes for a new roadmap preview and opens when a saved message failed, so that message can be retried.

Private drafts stay in account-keyed React state. An unsent helper message survives closing the helper. Unsaved settings are saved before a chat message or generation. Unknown outcomes retry the original mutation identity, and account changes clear private display and ignore late responses.
