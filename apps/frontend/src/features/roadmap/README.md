# Roadmap

`roadmap-planner.tsx` is the shell: it loads and polls the workspace, sends messages and writes, and recovers lost responses. It shows one of two views.

- **Saving:** planner changes save automatically shortly after each edit, without freezing the form, and any waiting edit is sent as the page closes. **Save settings** only appears if an automatic save fails. Saving a change can invalidate an open preview, as it does when settings are saved any other way.
- **Week:** study blocks show their start and end times, and an end time sets the block's length. **+ Add blocked-out time** adds blocked times to the same week, in a striped colour. One-day and monthly blocked times have no fixed weekday, so they sit under the grid.
- **Planner:** `settings-panel.tsx` writes the plan as one sentence travelling down a road. Each clause is a stop holding one setting, with highlighted parts to tap and change, and `blackout-rules.tsx` for repeating blackout days and time slots. The road is travelled up to the first required detail still missing and ends at Your runway, which holds Generate. Every runway number and duration resolution comes from `POST /planner/runway`.
- **Chat helper:** on screens wider than 1100px it docks to the right of the planner when the page opens, running nearly the full screen height with the page heading beside it, without taking keyboard focus, and stays closed if the user closes it. On narrower screens it overlays the page and opens from a button. On the roadmap page it also opens from a button. It starts on the first required detail the runway reports as missing, lists what is still needed, and fills in the form. With a plan, it requests a preview. It closes for a new preview and opens when a saved message failed, so that message can be retried.
- **Roadmap page:** no tabs; the Starting point view was removed. `task-planner.tsx` leads with the sessions as a to-do list, viewed by day or week, with the skills each session builds. The monthly view is a calendar with one row per week, showing milestones as bars, sessions as dots and each week's summary; choosing a row opens that week. Only the first planning week has dated sessions, so later weeks show their milestones instead. `roadmap-review.tsx` adds skill progress, then `RouteMap` draws the plan as a rising route to the goal, solid up to today and dotted for what is projected; the numbered milestone list in `milestone-timeline.tsx` carries the same facts as text. A preview applies only when accepted, and its sessions cannot be ticked.
- **Add a task:** on the active roadmap (never a preview), `add-task.tsx` adds one scheduled task of your own through `POST /api/v1/roadmaps/planner/tasks/add`: a title, the day, an optional skill from the plan's gaps (linked to its requirement and milestone), a time from that day's preferred/backup blocks or a custom start, and a duration. A failed save keeps the draft. The header shows the days left to the target date and the current planning week, counted in whole weeks as the planner does.
- **Evidence suggestions:** `evidence-proposals.tsx` shows one "Add this to your Skills Profile?" suggestion at a time. "Not now" hides it for this visit only; nothing is written until you confirm.

Ticking a session records it at once. A note on what was produced can follow, and unticking reopens the session and clears its note. `roadmap-calendar.ts` does the date arithmetic on plain local dates.

Private drafts stay in account-keyed React state. An unsent helper message survives closing the helper. Unsaved settings are saved before a chat message or generation. Unknown outcomes retry the original mutation identity, and account changes clear private display and ignore late responses. See the [Roadmap specification](../../../../../services/roadmap-service/SPEC.md).

New preview navigation is applied with the workspace update, before the preview becomes interactive. Returning to Configure retains the preview and is not reversed by a deferred view effect.
