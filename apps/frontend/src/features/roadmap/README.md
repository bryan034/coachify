# Roadmap

`roadmap-planner.tsx` is the shell: it loads and polls the workspace, sends messages and writes, and recovers lost responses. It shows configuration, a preview, or the active roadmap.

- **Saving:** planner changes save automatically shortly after each edit, without freezing the form, and any waiting edit is sent as the page closes. **Save settings** only appears if an automatic save fails. Saving a change can invalidate an open preview, as it does when settings are saved any other way.
- **Week:** study blocks show their start and end times, and an end time sets the block's length. **+ Add blocked-out time** adds blocked times to the same week, in a striped colour. One-day and monthly blocked times have no fixed weekday, so they sit under the grid.
- **Planner:** `settings-panel.tsx` writes the plan as one sentence travelling down a road. Each clause is a stop holding one setting, with highlighted parts to tap and change, and `blackout-rules.tsx` for repeating blackout days and time slots. The road is travelled up to the first required detail still missing and ends at Your runway, which holds Generate. Every runway number and duration resolution comes from `POST /planner/runway`.
- **Chat helper:** on screens wider than 1100px it docks to the right of the planner when the page opens, running nearly the full screen height with the page heading beside it, without taking keyboard focus, and stays closed if the user closes it. On narrower screens it overlays the page and opens from a button. For an active roadmap it is reached through Plan settings. It starts on the first required detail the runway reports as missing, lists what is still needed, and fills in the form. With a plan, it requests a preview. It closes for a new preview and opens when a saved message failed, so that message can be retried.
- **Roadmap page:** `roadmap-views.tsx` opens on Today and offers Week, Month, Milestones and Progress. The view and local date are reflected in the URL. `calendar-views.tsx` shows task lists, a 24-hour timeline and calendar task details. `progress-views.tsx` shows checkpoints, self-reported milestone outcomes, task/hour charts and pace. Figures are computed from service-projected sessions; they never change assessed competence.
- **Plan settings:** opens the existing configuration screen, including regeneration, source notices and chat. The header badge counts available updates. Return to roadmap preserves the saved plan.
- **Task details:** `task-form.tsx` edits the name, done-when criterion, selected skills, timed or anytime scheduling, duration, structured notes and optional confidence/difficulty ratings. Writes go through the session API with version checks. Original generated wording can be restored. Overlaps need an explicit save; failed saves retain edits.
- **Backlog:** `backlog.tsx` requests available slots or a proposed batch from the service. The user reviews proposed moves before applying them; skipping removes the task. No model call is required.
- **Preview:** `plan-preview.tsx` shows the first scheduled week, milestones, changes and any reconciliation decisions. It cannot record progress and only becomes active through Accept plan.
- **Evidence suggestions:** `evidence-proposals.tsx` shows one "Add this to your Skills Profile?" suggestion at a time. "Not now" hides it for this visit only; nothing is written until you confirm.
- **Outdated roadmap:** when the displayed plan's input hash differs from the latest CV, skills or career goal, a roadmap banner replaces the shared CV/career change banner and source notices. **Regenerate roadmap** uses the existing generation flow to prepare a preview for acceptance; it stays disabled while inputs are not ready or a request is in progress. A current preview clears the banner.

Ticking a task shows an optimistic update and rolls back if saving fails. Notes and self-ratings save separately through the task details. `roadmap-calendar.ts` handles plain local dates; `roadmap-day.ts` contains display arithmetic.

Private drafts stay in account-keyed React state. An unsent helper message survives closing the helper. Unsaved settings are saved before a chat message or generation. Unknown outcomes retry the original mutation identity, and account changes clear private display and ignore late responses. See the [Roadmap specification](../../../../../services/roadmap-service/SPEC.md).

New preview navigation is applied with the workspace update, before the preview becomes interactive. Returning to Configure retains the preview and is not reversed by a deferred view effect.

Roadmap displays the shared saved evaluation status. Missing/outdated data needs an explicit evaluation update before generation; completed current results are reused. An existing evaluation is polled at most 60 times at two-second intervals, within the 240-second total Roadmap operation budget.
